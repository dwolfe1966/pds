# SEO surface — deploy runbook (Vercel + Cloudflare path-split)

The `seo/` app is a standalone Next.js app that renders **only the `/people/*` tree**.
It ships to **Vercel** and is served on **idlookup.ai** via a Cloudflare path-split,
so the profile pages share the main domain's authority. The main Parcel SPA is
unchanged.

## 1. Deploy to Vercel
1. Vercel → **New Project** → import the `pds` repo.
2. **Root Directory: `seo`** (important — not the repo root).
3. Framework preset: **Next.js** (auto-detected). Build `next build`, output default.
4. No env vars needed for Phase 0 (fixtures). When BC ASK 0 lands, add the BC
   base URL / creds used by `lib/data.js`.
5. Deploy. You get a `*.vercel.app` URL — every page there carries `noindex`
   (`app/layout.js`) **and** `<link rel=canonical>` → `idlookup.ai`, so the
   vercel.app origin never competes for the index.

## 2. Cloudflare path-split (idlookup.ai)
Put Cloudflare in front of `idlookup.ai` and route by path:
- `idlookup.ai/people/*`  → **the Vercel deployment** (this app)
- `idlookup.ai/sitemap.xml` → **the Vercel deployment** (so the SEO sitemap is
  reachable on the public domain; Next serves it at `/sitemap.xml`)
- **everything else** (`/`, `/dashboard`, `/name/landing`, `/payment`, `/api`, …)
  → the existing Parcel SPA / current origin.

Implement with a Cloudflare Worker (fetch-and-proxy by `url.pathname`) or Origin
Rules / a rewrite pointing the matched paths at the Vercel origin. Preserve the
`Host` as `www.idlookup.ai` so canonicals + internal links stay on-domain.

## 3. robots.txt + sitemap (coordination — MAIN site owns robots)
Google reads robots for `idlookup.ai/people/*` from **`idlookup.ai/robots.txt`**,
which is served by the **main site**, not this app. Update the main site's
`robots.txt` to:
```
User-agent: *
Allow: /people
Sitemap: https://www.idlookup.ai/sitemap.xml
```
(This app's own `app/robots.js` only governs the vercel.app origin.) The sitemap
at `/sitemap.xml` is generated by this app (`app/sitemap.js`) and must be routed
to Vercel per step 2.

## 4. Prove it (Phase 0 definition-of-done)
1. Deploy is live at `idlookup.ai/people/…` through the proxy.
2. `view-source:` a leaf + a hub → confirm the full content **and** all JSON-LD
   blocks are in the initial HTML (no client JS needed).
3. Google Search Console → **URL Inspection** on a live `/people/.../{id}` URL →
   "Test Live URL" → confirm Googlebot renders it and sees the structured data.
   (Pages are `noindex`, so they won't index yet — that's expected; we're proving
   crawl + render.)

## 5. Flip to indexed (staged rollout)
When ready for the first staged batch: flip `robots` in `app/layout.js` to
`{ index: true, follow: true }` (or override per-route for a subset), keep the
canonical, submit the sitemap in GSC, and monitor Coverage + manual-action risk.
Thin/low-value combos already 404 (the hub/leaf seams return `notFound()`), so
they never enter the sitemap or the index.
