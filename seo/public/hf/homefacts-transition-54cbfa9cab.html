HomeFacts × IDLookup · transition plan

Take HomeFacts modern — without losing a dollar of its search equity.

HomeFacts' value is the ranking equity bound to its existing URLs. The strategy: our app fully replaces the 2013 site and answers those same URLs — NIC's codebase is never touched. We change what's behind each page, not its address.

The cardinal rule
Keep the URLs. Change what's behind them.

Rankings and backlinks accrue to specific URLs, not to "the site." So the migration's first job is to not move the URLs that hold equity. Our app fully replaces the 2013 site and serves those same addresses — the old PHP codebase is retired, not rewired. URL cleanup, if ever, comes later — carefully, and only once the domain is stable.

We replace the site — we don't rewire it

No one edits a line of HomeFacts' old code. Here's the whole switchover, in plain terms:

  1. We rebuild HomeFacts in our app — every page recreated at its exact existing web address.
  2. We test it side-by-side on a private preview until each page matches, at the same addresses.
  3. We point the domain at the new app. "homefacts.com" is just a name; today that name is wired to the old server. We change one setting so the name is wired to our app instead — same street address, but the mail now arrives at a new, modern building.
  4. The old 2013 site is switched off — retired, never edited. NIC's team touches nothing.
  5. Visitors and Google see the same web addresses — the pages behind them are simply modern now.

Under the hood: our app reproduces HomeFacts' addresses byte-for-byte (built from their own page list, so nothing breaks), and our preview addresses redirect into the live domain.

Phased rollout

Phase 0 · days

Inventory

Pull HomeFacts' real URL list + per-URL traffic (GSC / logs). Baseline rankings. This list is the migration spec.

Phase 1

Parity

Serve modern content at the top incumbent URLs, at their exact addresses. Self-canonical. No URL changes.

Phase 2

Consolidate

301 the idlookup.me prototype into homefacts.com. One clean home for the traffic; prototype becomes staging.

Phase 3 · optional

Modernize URLs

Only once stable, if worthwhile: clean up legacy .html URLs — high-traffic-first, monitored. Not required to succeed.

4

How the equity is protected

✓Zero changes to the 2013 app. The domain is pointed at our app; the old PHP stack is retired, not rewired. NIC engineering: none.
✓No URL restructuring. The content behind each page changes; the URL itself doesn't. Nothing is moved onto a new structure at takeover.
✓No mass redirects. Incumbent URLs stay live and self-canonical — only the prototype 301s, single-hop.
✓Byte-exact URLs. Generated from HomeFacts' own crawl, not guessed — so no mismatch 404s.
✓Sitemap discipline. High-value core submitted first; thin pages held — no crawl-flood indexing risk.
✓Coverage gate. Every top URL round-trip-verified (URL → render → identical canonical) before cutover.
✓Parity-first & reversible. We match before we improve; nothing destructive, staged behind a flag.
