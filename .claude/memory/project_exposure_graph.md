**EXPOSURE GRAPH v1 — BUILT 2026-08-04 (seo backend; auto-deploys; verified vs live Neon).** The spine every footprint feature plugs into. Files:
- `seo/lib/exposure-graph-db.mjs` — lazy self-creating tables (mirrors `breachMonitorDb` ensureTables). Tables: **`exposure_node`** (one node = subject×source×url; found_status, data_types, control_status[none/hidden/optout_requested/optout_confirmed/removed/reappeared/...], control_method[our_suppression/optery/onerep/manual/google_rar/...], external_ref, severity, sentiment), `exposure_event` (append-only history), `source_registry` (13 seeded: DigitalFootprint brokers + Google + idlookup + socials; drives per-source removal routing), `owner_annotation` (owner voice). `upsertNode` PRESERVES user control_status on re-scan (never clobber an action) EXCEPT `syncControl:true` for source-derived nodes (IDLookup). `summarizeNodes` = score+counts.
- `seo/app/api/exposure/route.js` — GET federates the columns we ALREADY OWN (IDLookup ← `getSuppressionState`; breaches ← `getMonitorState`) into nodes, returns `{nodes, registry, summary}`; POST records per-node control change+event, gated on `hasMappedIdentity`. App-key gated, CORS, degrades to empty.
- `seo/db/exposure-graph-schema.sql` — canonical schema reference.

**Design principles:** surface-agnostic (a broker/social/search/breach/AI node are the same row type → new surface = new data, not new schema); per-provider itemization native (node = the listing); vendor-agnostic control; **federate don't rebuild** (member_suppression, breach monitor, getSocialPresence are already columns). See [[project_identity_control_owner_voice]] (Hide is FUNCTIONAL on WSFY, not a stub), [[project_wsfy_self_build]], [[project_social_presence]], [[project_freemium_identity_community]].
