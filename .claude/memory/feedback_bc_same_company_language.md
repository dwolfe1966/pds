BC (ByteCrtrs) and PDS/idlookup are the **same company**. In documents, commit messages, and any
communication, do NOT use adversarial "us vs them" framing — e.g. "our CSR **vs** BC.admin", "we diverged
from BC", "BC is wrong". It reads as one team against another when it's one team with two tools/views.

**Why:** the owner biases toward working independently and knows he contributes to this framing, but that
independence is a working preference — it does NOT make BC "the enemy". Adversarial language is corrosive
inside one company and could leak into shared docs.

**How to apply:** frame differences as **"current business logic vs potential/target business logic"**, or
"the admin view vs the CSR view" (two representations of the same system), or "aligning the CSR with the
established admin logic". Use neutral words: *difference / align / reconcile / current vs proposed* — not
*vs / diverged / disagreed / mismatch-as-fault / beat*. When the CSR and admin tool differ, treat the admin
tool as the established/current logic we're aligning to, not an opponent. Retroactively fix any doc that
already reads this way (e.g. the 2026-07-23 CSR↔admin billing-alignment doc). Extends
[[project_bc_org_relationship]] (BC is internal, not a vendor) — that's about coordination; this is about
tone/language.
